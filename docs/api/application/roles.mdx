# Admin Roles

An admin role is a named set of admin permissions. A user with an admin role (and without root admin) can use the
Application API and the admin area, but only the endpoints whose **Admin permission** is in the role. Root
administrators have every permission. These endpoints manage the roles. To assign a role to a user, set
`admin_role_id` on the [user](/docs/api/application/users). `{role}` is the role's numeric `id`.

## The admin role object

`object` is `admin_role`.

| Attribute | Type | Description |
|-----------|------|-------------|
| `id` | integer | Role ID. |
| `name` | string | Role name. |
| `description` | string or null | Role description. |
| `color` | string or null | Display color. Free-form string, not validated. |
| `permissions` | array of strings | Permission strings granted to the role. Empty array if none. |

Admin roles have no includes.

## List roles

`GET /api/application/users/roles`

**Admin permission:** `roles.read`

Returns a paginated list of admin roles.

```bash
curl "https://panel.example.com/api/application/users/roles" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Accept: application/json"
```

### Query parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `per_page` | integer | No | 1 to 100. Defaults to `20`. See [pagination](/docs/api/introduction#pagination). |
| `page` | integer | No | Page number. |
| `filter[id]` | string | No | Partial match on the role ID. |
| `filter[name]` | string | No | Partial match on the name. |
| `sort` | string | No | `id` or `name`, optionally prefixed with `-`. See [filtering and sorting](/docs/api/introduction#filtering-and-sorting). |

### Response

`200 OK`

```json
{
  "object": "list",
  "data": [
    {
      "object": "admin_role",
      "attributes": {
        "id": 2,
        "name": "Support",
        "description": "Front-line support staff",
        "color": "#3b82f6",
        "permissions": ["overview.read", "users.read", "servers.read", "tickets.read", "tickets.message"]
      }
    }
  ],
  "meta": {
    "pagination": {
      "total": 1,
      "count": 1,
      "per_page": 20,
      "current_page": 1,
      "total_pages": 1,
      "links": {}
    }
  }
}
```

## List available permissions

`GET /api/application/users/roles/permissions`

**Admin permission:** `roles.read`

Returns every permission group that can be assigned to a role, with descriptions. A permission string is the group
name and a key joined by a dot, for example `servers` and `read` give `servers.read`.

### Response

`200 OK`

```json
{
  "object": "role_permissions",
  "attributes": {
    "permissions": {
      "overview": {
        "description": "Permissions to allow administrator to view the index page.",
        "keys": {
          "read": "Read the contents of the overview."
        }
      },
      "settings": {
        "description": "Permissions to allow changing basic admin settings.",
        "keys": {
          "read": "Read the panel settings.",
          "update": "Update the panel settings."
        }
      }
    }
  }
}
```

The example is shortened. The full list is in the [permission reference](#permission-reference) below.

## Get a role

`GET /api/application/users/roles/{role}`

**Admin permission:** `roles.read`

Returns a single admin role.

### Response

`200 OK`

```json
{
  "object": "admin_role",
  "attributes": {
    "id": 2,
    "name": "Support",
    "description": "Front-line support staff",
    "color": "#3b82f6",
    "permissions": ["overview.read", "users.read"]
  }
}
```

## Create a role

`POST /api/application/users/roles`

**Admin permission:** `roles.create`

Creates an admin role. New roles are always stored with a `sort_id` of `99`.

### Request body

JSON body.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Up to 64 characters. |
| `description` | string or null | No | Up to 255 characters. |
| `color` | string or null | No | Any string. |
| `permissions` | array of strings or null | No | Permission strings. Only strings listed in the [permission reference](#permission-reference) are stored; anything else is silently dropped. |

Logs the activity event `admin:roles:create`.

### Response

`200 OK`. The body is the created `admin_role` object.

## Update a role

`PATCH /api/application/users/roles/{role}`

**Admin permission:** `roles.update`

Updates an admin role. Only the fields you send are changed, but `name` is always required.

### Request body

JSON body.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Up to 64 characters. |
| `description` | string or null | No | Up to 255 characters. |
| `color` | string or null | No | Any string. |
| `permissions` | array of strings or null | No | Replaces the role's permissions. Only strings listed in the [permission reference](#permission-reference) are stored; anything else is silently dropped. |
| `sort_id` | number | No | Sort position. |

Logs the activity event `admin:roles:update`.

### Response

`200 OK`. The body is the updated `admin_role` object.

## Update a role's permissions

`PATCH /api/application/users/roles/{role}/permissions`

**Admin permission:** `roles.update`

Replaces the role's permissions and nothing else. Only strings listed in the
[permission reference](#permission-reference) are kept; anything else is silently dropped.

### Request body

JSON body.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `permissions` | array of strings or null | No | The new permission list. If omitted or `null`, the role's permissions are cleared. |

Logs the activity event `admin:roles:update-permissions`.

### Response

`200 OK`. The body is the updated `admin_role` object.

## Delete a role

`DELETE /api/application/users/roles/{role}`

**Admin permission:** `roles.delete`

Deletes an admin role. In the same transaction, every user with this role has `admin_role_id` set to `null` and
`root_admin` set to `false`, so those users lose admin access.

Logs the activity event `admin:roles:delete`.

### Response

`204 No Content`
